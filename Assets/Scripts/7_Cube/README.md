# GPU Cube Rigidbody (7_Cube)

이 폴더는 Unity PhysX Rigidbody 컴포넌트를 큐브마다 생성하지 않고, Compute Shader에서 동일한 질량·크기의 3D 강체를 계산합니다. 위치·회전·선속도·각속도와 충돌 접촉은 GPU에 남고, 큐브 전체를 한 번의 `Graphics.RenderMeshIndirect` 호출로 그립니다.

## 기존 코드 분석

- `GPUCube_gpt.cs`: GPU 버퍼 생성, 공간 격자 구성, 충돌 제약 생성, Jacobi 충격량 반복, 간접 렌더링을 담당했습니다.
- `7_Compute.compute`: 27개 인접 셀 탐색, OBB의 15개 분리축 검사(SAT), 면 클리핑/모서리 접촉, 각운동량을 포함한 충격량 계산이 이미 있었습니다. 이 SAT 및 접촉면 생성 코드를 유지·보완했습니다.
- `7_Cube.shader`: GPU 위치와 쿼터니언을 읽는 URP 간접 인스턴싱 셰이더입니다.

기존 대규모 실행의 문제:

1. `(10, i * 5 + 1, 10)` 생성으로 200m 공간 격자 안에는 처음 약 40개만 들어갔습니다. 나머지는 큐브 간 충돌 대상에서 빠졌습니다.
2. 100만 셀에 Hillis–Steele 전역 스캔을 약 20회 실행했습니다.
3. 실제 접촉 수가 0이어도 최대 400만 접촉 스레드를 연결/반복 계산했습니다.
4. 가변 `Time.deltaTime`, 마찰 부재, 접촉 수와 무관한 고정 완화 계수로 적층 안정성이 제한됐습니다.
5. 경계에서 큐브의 회전된 크기를 고려하지 않았고 격자 밖의 위치를 복구하지 않았습니다.
6. 접촉 버퍼 초과가 조용히 무시됐고 재활성화/여러 시뮬레이터의 자원 관리가 없었습니다.

## 변경한 실행 구조

1. GPU에서 격자 내부의 여러 층에 겹치지 않게 초기화합니다.
2. 누적 시간 기반의 고정 스텝을 사용합니다. 프레임당 최대 스텝을 넘는 시간은 버려 과부하가 누적되는 것을 막고, `DroppedSimulationSeconds`에 기록합니다.
3. 셀 카운트 → 256스레드 Blelloch 블록 스캔 → 상위 블록 스캔 → 하위 오프셋 합산으로 격자를 구성합니다. 100만 셀의 전체 prefix 구성은 5회 디스패치입니다.
4. 27개 인접 셀, 외접 구 빠른 제외, OBB SAT, 접촉면/모서리 생성 순으로 큐브 쌍을 검사합니다. 각 쌍은 한 번만 생성합니다.
5. 6개 경계 평면도 정적 강체 접촉으로 계산합니다.
6. GPU가 실제 접촉 수로 간접 디스패치 인자를 생성합니다. 65,535 스레드 그룹을 넘는 접촉은 2차원 디스패치로 처리합니다.
7. 접촉별 충격량 계산과 물체별 합산을 분리해 float atomic과 속도 버퍼 경쟁을 피합니다. 법선 충격량, Coulomb 마찰, 반발, 쿼터니언 회전을 처리합니다. 겹침은 별도의 위치 보정으로 줄이고, 거의 같은 SAT 축에서는 면 접촉을 우선해 적층이 무너지는 것을 줄입니다.
8. GPU 위치·회전을 그대로 렌더링합니다. 월드 좌표 변환과 간단한 면별 음영을 적용했습니다.

## 설정과 범위

- 중심이 원점이고 크기가 `(1, 1, 1)`인 Cube mesh를 사용합니다. 물리 질량은 1, 관성 텐서는 대각 성분 `1/6`입니다.
- 컨테이너는 월드 좌표 `(0,0,0)`부터 `(200,200,200)`까지입니다. 컴포넌트 Transform은 시뮬레이션 좌표계를 변경하지 않습니다.
- `Count`, `Max Contacts`는 버퍼 생성 시 확정됩니다. Play 모드를 다시 시작하거나 컴포넌트를 껐다 켜면 변경값이 적용됩니다.
- 접촉 버퍼는 접촉당 76바이트, 물체 버퍼는 물체당 약 88바이트, 격자는 약 12MB입니다. 접촉 용량을 늘리면 VRAM 사용량도 늘어납니다.
- `RequestedContacts`, `PeakCellOccupancy`, `InvalidBodies`는 1초마다 비동기로 읽는 한 스텝의 표본입니다. 최대 접촉 용량을 넘으면 경고합니다. 진단을 끄면 읽기도 중지됩니다.
- 이 구현은 동일 크기의 동적 큐브와 6개 정적 평면 전용입니다. 임의 MeshCollider, Unity 충돌 콜백, 조인트, 개별 질량, PhysX 상호작용, CCD, sleeping, 접촉 warm-start는 구현하지 않았습니다.
- 이산 충돌 방식이며 선속도 30m/s, 각속도 20rad/s로 제한합니다. 고속 충돌·매우 높은 적층에서는 더 작은 시간 간격과 많은 반복이 필요합니다. 조밀한 한 셀에 모든 물체를 겹치게 배치하면 여전히 최악의 경우 O(N²)입니다.
- 저장된 씬의 `Count`/`Solver Iterations`는 C# 기본값 변경만으로 갱신되지 않습니다. 현재 `SampleScene`의 `7_Cube`는 100,000개, 접촉 용량 2,400,000개, 24회 반복으로 설정했고 카메라도 배치했습니다. 씬을 열고 Play 하면 됩니다.

## 재현 가능한 검증

`Tools > GPU Cubes` 메뉴:

- `Run GPU Regression Checks`: 실제 GPU에서 100만 셀 prefix scan, 떨어진 큐브, 충돌 후 분리, 운동량, 회전 반응, 바닥 마찰, 간접 실행 인자, 버퍼 초과, 65개 tail thread, 해제 후 재초기화를 검사합니다.
- `Run 100k GPU Soak` / `Run 200k GPU Soak`: 매 Editor tick에 고정 스텝을 실행하고 접촉 수·비정상 상태·최종 좌표·회전과 관통 깊이를 검사합니다.
- `Stop GPU Soak`: 진행 중인 검증을 종료합니다.

검증은 숨겨진 임시 오브젝트를 만들며 씬을 교체하거나 저장하지 않습니다. GPU 읽기로 동기화하므로 로그의 wall time은 게임 FPS 또는 순수 GPU 시간과 다릅니다. 실제 성능은 Development Player와 Unity GPU Profiler에서 따로 측정해야 합니다.

## 2026-10-09 실행 결과

Unity 6000.3.18f1 / NVIDIA GeForce RTX 4060, 120Hz 고정 스텝, 24회 반복, 초기 8층 배치:

| 개수 | 스텝 / 시뮬레이션 시간 | 최대 접촉 수 | 버퍼 메모리 | 최종 최대 / 평균 관통 깊이 |
|---:|---:|---:|---:|---:|
| 100,000 | 360 / 3초 | 596,800 | 193.8 MiB | 0.0442 / 0.0106m |
| 200,000 | 360 / 3초 | 1,192,426 | 376.2 MiB | 0.0466 / 0.0105m |

두 실행 모두 접촉 버퍼 초과·비정상 수치·컨테이너 이탈이 없었습니다. GPU 원자 연산의 실행 순서 때문에 재실행 시 접촉 수와 수치는 약간 달라집니다. 검증 기준은 최종 최대 관통 0.15m 미만, 평균 0.03m 미만입니다. 완전한 무관통·결정론적 해법은 아닙니다.

C# 빌드와 Compute 커널 16개가 모두 경고·오류 없이 컴파일됐으며 실제 GPU 회귀 검사도 통과했습니다. Play 모드에서 100,000개를 렌더링하고 `Time.frameCount`가 372 → 374로 진행한 것을 확인했습니다. 당시 10.17초의 시뮬레이션 동안 접촉 표본 667,662개, invalid 0, overflow false였습니다.

**성능 한계:** Editor Play 검사에서 `DroppedSimulationSeconds`가 증가했습니다. 현재 품질 설정은 RTX 4060 Editor 환경에서 실시간 120Hz/60FPS를 보장하지 않으며, 부하가 높으면 물리 시간이 느리게 진행됩니다. 12회 반복으로 낮춘 실험은 최대 관통 약 0.209m로 품질 기준에 실패해 기본값 24회를 유지했습니다. 목표 FPS가 정해지면 sleeping, 접촉 캐시, manifold 축약 등 추가 최적화와 Player GPU 프로파일링이 필요합니다.

자동화 연결에서는 Play 진입 시 Pipeline descriptor 파일의 일시적 sharing violation이 관찰됐습니다. 이는 솔버 오류가 아니며 이후 Editor 명령과 렌더링 검증은 정상적으로 완료됐습니다.

자동화 검증을 위해 `com.unity.pipeline` 패키지를 추가했습니다. 런타임 솔버는 이 패키지 API를 사용하지 않습니다.

API 참고: [Unity ComputeShader.DispatchIndirect](https://docs.unity3d.com/ScriptReference/ComputeShader.DispatchIndirect.html), [GraphicsBuffer.Target.Raw](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/graphicsbuffer/target/raw).
